Cyber Threat Intelligence (CTI) turns raw data into context for faster threat detection. Tactical intelligence uses Indicators of Compromise (IOCs) such as IP addresses, file hashes, or URLs tied to known malicious activity. Operational intelligence covers TTPs (tactics, techniques, and procedures), for example the MITRE ATT&CK framework, which helps [hunt threats](/blog/threat-hunting-peak-framework/) and improve alerts.

CTI comes from internal reports, open sources (OSINT), sharing groups (ISACs), or commercial feeds. Using CTI reduces false positives and speeds up investigations. Sharing findings helps everyone stay prepared.

### DNS Response Policy Zones

DNS Response Policy Zone (RPZ), also known as a DNS firewall, addresses a blind spot in traditional firewalls.

By default, a traditional firewall such as pfSense looks at IP addresses (numbers like `192.0.2.1`), not domain names (like `evil-malware-site.com`).

Because one IP address can host thousands of different websites through cloud providers such as AWS or Cloudflare, a traditional firewall cannot easily block just one bad website by its IP without accidentally blocking hundreds of safe ones. A DNS firewall solves this by blocking the specific name before it is resolved to an IP address.

The National Council of ISACs maintains a list of sharing communities focused on critical infrastructure: [National Council of ISACs](https://www.nationalisacs.org/member-isacs-3).

## File hashes

There are multiple types of hashing algorithms, but the most common are Message Digest 5 (MD5) and Secure Hashing Algorithm (SHA) 1 to 3. One of the main distinctions between these hashes is the length of the key used in the function: 128 bits for MD5, 160 bits for SHA-1, and up to 512 bits with SHA-2 or SHA-3.

How to identify a hash:

- **MD5:** 32 hexadecimal characters. Older and prone to collisions, but still widely used.
- **SHA-1:** 40 characters. Also older, but common in legacy systems.
- **SHA-256:** 64 characters. The modern standard for unique file identification.

A file hash is a fixed-size string of characters generated by running the contents of a file through a mathematical algorithm. A hash value helps verify that a file has not been corrupted or modified in transit. Hash values are also useful for identifying malicious files on a network by comparing the hash of a suspicious file against already known malicious ones.

Changing a single bit in a file results in a different hash value. That is why hash-based IOCs sit at the bottom of the Pyramid of Pain. Still, it is a low-effort check, and a matching result can save a lot of time during an investigation.

## AlienVault OTX

The Alien Labs Open Threat Exchange (OTX) provides access to a global community of threat researchers and security professionals. Users can manually search through indicators of compromise, review "pulses" generated by users, or contribute their own security information: [otx.alienvault.com](https://otx.alienvault.com/).

## VirusTotal

VirusTotal analyzes suspicious files, domains, IPs, and URLs to detect malware and other breaches, and automatically shares them with the security community. Its API allows uploading and scanning files, submitting and scanning URLs, accessing finished scan reports, and making automatic comments on URLs and samples without using the HTML website interface. In other words, it allows building simple scripts to access the information generated by VirusTotal: [virustotal.com](https://www.virustotal.com/gui/home/upload).

![VirusTotal security vendor analysis for a file hash](/blog/threat-intelligence-essentials/virustotal-analysis.png)

To see URLs related to a hash: open VirusTotal, go to **Behavior**, then **Network communication**, and inspect where the HTTP requests go.

## Hybrid Analysis

Hybrid Analysis is a free malware analysis service for the community. Files can be submitted for in-depth static and dynamic analysis: [hybrid-analysis.com](https://www.hybrid-analysis.com/).

## PhishTank

PhishTank is a free community site operated by Cisco Talos Intelligence Group. Anyone can submit, verify, track, and share phishing data. You can register, explore the site, test your ability to recognize phishing, and help the community by verifying items submitted by other users: [phishtank.com](https://www.phishtank.com/).

## MISP

MISP, formerly the Malware Information Sharing Platform, is an open-source and free threat intelligence platform with open standards for sharing threat information. It can store, share, and support work on intelligence at large. The project is now led by a team of volunteers and includes tools that promote the sharing of structured information within the security community and beyond: [misp-project.org](https://www.misp-project.org/).

## Malware notes

- **Mirai:** targets Linux devices, mainly routers and IP cameras. Infected devices can become part of large network attacks and DDoS campaigns. SHA-256: `0d1bc013bcf23de96590a57fbac2f54f239a21602708cd2bdeed52f06930eea4`
- **Emotet:** an advanced Trojan primarily spread through phishing email attachments and links. Once clicked, the payload launches. The malware then attempts to proliferate within a network by brute-forcing user credentials and writing to shared drives. Relevant ATT&CK techniques: Brute Force: Password Guessing (T1110.001), Valid Accounts: Local Accounts (T1078.003), and Remote Services: SMB/Windows Admin Shares (T1021.002).

## Detection data and Splunk notes

In Splunk, the `sourcetype` field identifies the data structure of an event. It determines how Splunk formats the data during indexing and how it is displayed during searches.

Basic searches:

```spl
index=* | stats count by index | fields index
```

```spl
| metadata type=hosts index=*
```

Common SPL commands mentioned in these notes: `search`, `table`, and `stats` (used for counts).

Data models include Authentication, Email, Endpoint, Malware, Data Loss Prevention, and Network Traffic.

### Common data sources

| Data source | Description |
| --- | --- |
| **Files and directories** | Most data that you might be interested in comes directly from files and directories. |
| **Network events** | Splunk can index remote data from any network port and SNMP events from remote devices. |
| **IT Operations** | Data from IT Ops, such as Nagios, NetApp, and Cisco. |
| **Cloud services** | Data from cloud services, such as AWS and Kinesis. |
| **Database services** | Data from databases such as Oracle, MySQL, and Microsoft SQL Server. |
| **Security services** | Data from security services such as McAfee, Microsoft Active Directory, and Symantec Endpoint Protection. |
| **Virtualization services** | Data from virtualization services such as VMware and XenApp. |
| **Application servers** | Data from application servers such as JMX and JMS, WebLogic, and WebSphere. |
| **Windows sources** | The Windows version of Splunk accepts a wide range of Windows-specific inputs, including Windows Event Log, Windows Registry, WMI, Active Directory, and performance monitoring. |
| **Other sources** | Other input sources are supported, such as FIFO queues and scripted inputs for getting data from APIs and other remote data interfaces. |

HTTP status codes: HTTP 400 and 500 status codes indicate that a request to a server failed. 4xx codes mean the client made an error (e.g., bad syntax). 5xx codes mean the server is aware it failed to fulfill a valid request. 403 Forbidden means the server understood the request but refuses to authorize it (e.g., lack of permissions).

The `WinEventLog` sourcetype is a good place to start.

Useful data categories include authentication data, network traffic, proxy or gateway logs, and application, endpoint, or server logs. Examples include logs from IDS/IPS devices and firewalls.

The `transaction` command groups related events together.

Other terms from these notes:

- **VPC:** virtual private cloud.
- **Zero trust:** a security model that does not implicitly trust users or devices based on network location.
- **Defense in depth:** multiple layers of security controls.
